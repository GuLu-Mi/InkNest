# 测试策略与验收矩阵

关联 REQ-001–030、NFR-001–008。本文定义测试方法和需求用例，包含尚未提供的功能要求；实际使用边界见[已知限制](known-issues.md)。

## 1. 分层策略

| 层次 | 工具或方法 | 验证对象 |
| --- | --- | --- |
| 单元 | Vitest | 编码、序列化、路径分类、标题 ID、dirty、版本推进、调度状态 |
| 集成 | Vitest + 独立临时目录 | 真实读写、替换、文件变化、权限、恢复索引、历史清理 |
| UI / E2E | Playwright Electron 驱动 | 打开、编辑、保存、切换模式、提示和焦点 |
| 原生人工 | 真实 Windows / macOS | 系统文件关联、菜单、安装器、中文输入法、辅助技术 |
| 故障与性能 | 子进程中断、I/O 故障注入、性能采样 | 崩溃恢复、磁盘失败、时序、延迟、内存 |

Playwright Electron 驱动需在固定版本和实际桌面环境核验；不能依赖自动化代替系统输入法和安装器验证。[官方说明](https://playwright.dev/docs/api/class-electron)

测试只操作 `tests/fixtures` 的只读样本副本和临时目录。故障注入接口仅存在于测试装配，不能打入生产包。

## 2. 样本与隔离环境

仓库固定样本位于 `tests/fixtures/`：

- `basic-zh.md`、`reader-layout.md`：Markdown 语法、安全边界和布局样本。
- `encoding/`：以十六进制保存的编码与换行样本。
- `images/`：本地生成的固定图片，来源见该目录 README。
- `nsis/`：安装器完整性检查样本及许可、校验和。

其他图片边界、性能文档、恢复索引、文件冲突和 I/O 故障由各测试在临时目录构造。使用固定数据或 seed，保留大小和 hash，测试结束后清理临时目录；不下载不明文件或使用个人文档。

运行方式见[开发指南](development.md)。原生输入法、选择器、读屏、安装器、文件占用和全屏交互应在 Windows 与 macOS 桌面环境分别测试。

发布工具测试覆盖升版本命令及锁文件一致性、不同版本的输出与样本名称、真实 ASAR/NSIS 提取、缺失或错误附件、重复发布、标签提交不符、上传中断与草稿恢复。工作流集成验证使用 Release 的仅构建模式，不能用测试版本覆盖已发布版本。真实远端发布与接口替身测试分别报告。

## 4. 关键回归场景

- 同规范文件只有一个可写会话，最多 20 标签；后台保存和恢复不抢焦点。开关侧栏、滚动、查找及编辑状态按会话隔离。
- 自动保存 1000ms/10000ms、恢复 2000ms/10000ms；IME 等待、屏障、迟到回执、撤销、失败后暂停与明确恢复。
- 历史保存后立即可见，自动组固定 60000ms、100 节点/30天/200MiB、A→B→A、schema1 迁移、retired 回收、租约和失败独立报告。
- 历史还原的两阶段写入、preservedCurrent、diskUncertain、丢回复原请求核对及可撤销事务；只读/缺失来源只导出、不强行还原。
- 恢复双快照、manifest 中断、已损坏最新条目、discard marker、容量真实计费、未知文件不擅自删除；不能把“双快照”直接当成“任意损坏可恢复”。
- 非模态侧栏与正文滚轮/选择/编辑并行；280px 目录、300px 历史及其宽度上限；960px 两侧栏并排阈值，800×600 与 200% 缩放。
- 图片四种格式、EXIF/动画像素预算、越界与畸形容器、单图主动授权和查看器；另存为后资源 URL 变化且新图片实际解码。
- 查看器缩放与旋转不重建当前img、不改写图片/Markdown，不扩张资源授权；校验旋转包围盒与实际滚动范围、未触边锚点误差≤2 CSS px。合成Ctrl wheel只验证事件路径；真实Mac触摸板、Windows Precision Touchpad及两平台鼠标须另行原生验证，构建和E2E通过不能替代手势手感验收。
- 链接目录/附件/外部协议路由、源失效、焦点/活动代数、显式锚点与标题 slug；不能调用任意 shell/IPC。
- 搜索真实展示来源、中文及 Unicode、非重叠完整计数、150ms 防抖、取消旧结果；替换使用原事务，全部替换单次撤销。
- 系统冷/热/重复打开与 renderer-ready 队列；主题写入乱序、损坏配置、动效与撤销历史不变。
- 生产窗口精确 API 白名单、CSP nonce、Node/上下文/沙盒/网络/导航边界；NSIS 外层和内嵌卸载器双 CRC。

## 5. 测试结果的解释

结果至少记录源码版本、工具链、平台/架构、命令、退出码、用例范围、失败与复测，以及原始证据位置。测试通过只覆盖其实际断言：观察内存并打印数字的用例通过，不代表数字符合 NFR。生成安装包不代表安装和运行测试通过。

完整 E2E 可以使用测试进程中的 `INKNEST_PRESENTATION_TEST_DRIVER=controlled` 装配；必须明确标记全屏边界受控。真实中文 IME、读屏、系统选择器/确认、最低系统、Windows 文件锁及全屏进出另行验证。Electron 启动时启用 sandbox，不能为了跑通自动化放宽生产限制。

I/O 错误注入、真实子进程 SIGKILL、物理磁盘满、真实系统占用和断电分别计证据。测试只使用固定样本副本和隔离临时目录，禁止改写用户真实 Markdown。

性能记录固定样本 hash、冷/热条件、采样次数及统计口径。启动/打开的正式 30 次样本、输入分位数、单文档内存和 100 次循环后的增长分别比较目标。进程工作集汇总可能重复计共享页，必须说明口径；1→20 标签增长不能冒充同样本 100 次切换增长。

运行报告、失败日志和截图保存在本地忽略目录。提交说明可列出检查结果，影响使用的问题记录在[已知限制](known-issues.md)。
