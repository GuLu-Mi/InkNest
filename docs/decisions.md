# 设计取舍

本文说明当前技术选择及其代价。具体行为以[产品需求](requirements.md)、[交互](interaction.md)和[持久化协议](persistence.md)为准。

## ADR-027：统一版本与手动发布

关联 REQ-025、NFR-003/008。`package.json` 是版本来源，npm 升版本命令同步锁文件，构建目录与样本名称由同一配置派生。GitHub 仅从 `main` 手动启动一个 Release 工作流，固定源提交，双平台检查成功后才创建标签、上传并校验附件、发布 Release。普通推送不发布，已发布版本不覆盖；保留只构建和预览模式。

采用串行发布任务与可恢复草稿，上传失败可在同一提交重试，已上传附件必须与当前摘要一致。代价是重跑构建若产生不同字节，需要明确处理不匹配的草稿附件，不能静默替换；收益是版本、代码和下载产物始终可核对。

## ADR-028：开发副本定向注销

关联 REQ-020/025、NFR-003/008。macOS允许同一应用的多个副本注册为文档处理程序；隐藏构建目录不足以阻止运行后的注册。采用开发脚本在构建/验证结束后，通过系统工具 `lsregister -u` 注销本次受管理的构建路径，先核验规范路径与应用标识。正式安装和默认程序保持原状，不改产品bundle ID、版本或文件关联声明，不对系统数据库做全量重建。

该命令是开发主机维护工具，不作为应用运行时接口或preload能力；系统工具失败必须报告。代价是进程强杀无法保证退出清理，手动运行副本也会再次注册，需在退出测试副本后按确切路径清理。

## ADR-001：桌面技术栈

**采用：Electron + Vue 3 + TypeScript + electron-vite。**

比较：Electron便于统一桌面Web渲染环境；Tauri有减少随包运行时的优势，但增加Rust工具链与WebView差异；PySide6可使用Python生态，但复杂Web排版与编辑仍需集成相关组件。

当前重点是可靠阅读和保存，接受Electron体积成本。运行时体积与内存是这一选择的主要代价。

## ADR-002：源码编辑与文本保真

**采用：CodeMirror 6 编辑原始Markdown，markdown-it提供预览。**

替代项为Monaco和富文本/WYSIWYG内核。当前不需要IDE能力，且不接受HTML转回Markdown造成不可控文本改写。未来若引入WYSIWYG，应单独定义方言范围和往返兼容测试，不能直接替换现有存储模型。

## ADR-003：直接文件与无服务器

**采用：原文件直接读写，配置/恢复/历史保存在userData。**

不导入内部文档库，不启服务端。SQLite等数据库可在真正出现大规模元数据检索需求时重评；当前JSON与内容快照足够，但必须具备原子提交和schema版本。

## ADR-004：保存完整性优先

**采用：同文件串行、快照绑定、写前冲突核对、同目录原子替换、独立恢复。**

拒绝每次输入直接writeFile、固定时间窗忽略watcher和预览HTML回写。接受普通文件系统存在跨进程竞争窗口，不做绝对不丢稿承诺。

## ADR-007：权限与离线

**采用：raw HTML关闭、远程资源禁止、本地资源按会话根目录授权、沙盒与受限IPC。**

不为图片方便开放整个磁盘，不因没有云同步就信任本地文档。远程图片加载、SVG、公式或图表若新增，必须修改安全及验收设计。

## ADR-008：平台与编码

**采用：Windows11 x64和macOS14+ arm64；UTF-8编辑优先。**

暂不承诺旧Windows、Intel Mac、Linux或任意编码。无法可靠保真的编码/混合换行只读，转换需另存为。扩大平台或编码范围先补原生测试环境和保真案例。

## ADR-009：默认交互与阈值

**采用：简体中文、默认阅读、标准系统窗口、容量与性能数值使用需求表。**

容量与性能目标集中定义，避免界面、文件服务和测试各自使用不同阈值。

## ADR-011：CodeMirror 生产样式与关闭保护

CodeMirror 动态样式使用运行时随机 nonce，与协议响应头、HTML 和 EditorView 绑定；不放宽 CSP 的任意 inline style 权限，文档输入不能提供 style/nonce。

主进程通过一次性关闭挑战获取冻结的最新正文，取消或失败保留会话并释放冻结。最终编辑事务入口同时检查冻结、只读和容量限制，防止历史命令绕过保护。代价是退出时需要一次跨进程状态交换，收益是保存和关闭使用同一份确定快照。

## ADR-012：快照保存与字节级确认

**采用：write-file-atomic 8.0.0 作为替换基础，主进程独立负责快照串行与成功 token 链。**

关联 REQ-009/010/011/012/013/019，NFR-001。不依赖库内部串行代替业务版本检查，也不把 mtime 当作权威内容版本。回执确认提交的源码快照，写后 token 来自实际落盘原始字节及身份；前导 U+FEFF 的 BOM 歧义不通过重新解码回写会话来消除。关闭保存沿一次性冻结挑战返回匹配回执，候选读取失败不撤销已成功保存的正式基准。库提供的最后检查点在临时文件创建后、数据写入前，不能承诺第三方写入的全局 CAS；平台/断电边界见 persistence.md。

## ADR-013：单窗口多会话与身份隔离

**采用：单窗口、最多20标签、单活动视图。** 关联REQ-001/008/013/020/021/023/026、NFR-001/002/006/008。各文档独立CodeMirror状态与调度；registry按规范路径/dev/ino唯一登记，owner+docId+epoch授权，后台保存与资源不依赖active。整窗关闭先冻结全部、逐个保存、全部成功才释放。

## ADR-014：自动保存与独立数据保护

**采用：默认自动保存，恢复草稿、历史与关闭保护独立维护。** 关联REQ-009至016/019/022、NFR-001。无修改不写、1000/10000ms调度、输入法保护；每文件独立队列，首次自动覆盖先存旧版本、错误暂停，恢复不自动覆盖。手动保存不改变自动保存策略；文档工具栏、文件菜单与快捷键共用原事务，底部展示保存状态（入口布局见 ADR-031）。

## ADR-015：阅读排版与产品文案

**采用：1080px正文、16px/1.75、小型编辑/预览入口与真实就地错误。** 关联REQ-002/008/017/024/027、NFR-007/008。只渲染活动视图；错误提示就地显示，恢复备份与正式保存使用不同文案，避免误导内容已落盘。

## ADR-016：恢复来源已打开时保留双方

**采用：激活既有标签并返回TARGET_OPEN，提示先处理、关闭后恢复。** 关联REQ-014/026、NFR-001。restoreRecovery(id)没有最新CurrentState交换，不能用可能落后的checkpoint判断是否可替换当前内存；因此即使已有标签看起来干净，也不一键覆盖。恢复记录继续保留，其他同路径会话保存不会按路径误清理。代价是多一步关闭；若以后需要一键替换，应另行设计受控的最新状态交换。此行为保留当前内存与恢复记录，避免无最新快照的隐式替换。

## ADR-017：历史原位还原采用受控双写事务

**采用：REQ-028作为REQ-016的受控例外。** 关联REQ-010/011/012/013/014/015/016/028、NFR-001/002/008。历史还原作为显式能力；普通查看/原始字节导出仍隔离于可写会话。历史还原使用独立固定业务IPC，不给普通保存增加restore触发或force。

选择先保护A并保存dirty B、再强制保护B并写历史C，复用SaveCoordinator内部原子步骤和既有有界请求登记。两次历史备份都必须成功，不使用普通手动保存的跳过选项。逐会话还原门控及历史清理准入保护确认全过程，既有写入先排空，队列内不再调用排队save。成功新链拒绝旧token，部分成功和写后不确定分别通过preservedCurrent/diskUncertain反馈，禁止盲目回滚。

renderer保留当前CodeMirror状态，以经过完整回执核对的专用接纳提交一个可撤销事件并原子更新基准。代价是一个较普通保存更严格的业务事务和阶段回执；收益是还原失败仍能定位完整当前内容，丢失回复不静默再写旧正文。保留当前BOM/EOL、历史结尾换行及既有配额；不恢复权限、图片副本或目录。

采用每工作区最多一个未核实还原操作的临时保留及原请求回执重放。拒绝以伪造新revision解除renderer B/main C分歧，也不增加任意重同步IPC。源编辑保持独立hold，其他标签仍可用；核对完成、明确终态或会话释放时删除上下文。待核对期间释放可见历史正文并暂停新历史读取。关闭期间允许已有精确回执只读重放，新还原仍禁止。代价是传输故障持续时源编辑与历史浏览暂不可用，换取B的可撤销保留、主进程保护不变及可执行的恢复动作。

## ADR-018：共享标题模型与净化后应用锚点

**采用：一次markdown-it token解析、序号ID及活动来源专属目录协调器。** 关联REQ-003/008/024/026、NFR-002/007/008。目录与渲染共享 inknest-heading-序号，安全净化后由应用添加，不扩展原始 HTML 白名单。主动链接通过标题 slug 与受限显式锚点映射到应用 ID。标题重排后的折叠迁移使用层级、标题、父路径、重复数量和出现次序，歧义重置而非错误折叠其他标题。

采用useOutline协调活动来源、组合输入门控、150ms刷新和响应布局；OutlineState独立纯逻辑，App仅编排。后台不解析或持有DOM；历史目录仅绑定当前所看快照，未打开恢复预览没有资源授权。成本是当前/历史目录拥有各自状态，收益是不会用当前标题误跳历史、不会被动提交输入法或污染撤销/保存源。

## ADR-019：原生全屏确认与只读演示快照

REQ-008/012/013/024/026/029，NFR-001/002/007/008。采用窗口所有的PresentationController，固定setPresentation请求只表达目标，异步原生事件与实际isFullScreen才确认状态；10秒看门狗处理失败及晚到事件，不用CSS冒充全屏。退出保留此前系统全屏，系统离开全屏同步退出演示；窗口销毁清理全部监听/计时器。

演示固定捕获IME已提交的当前正文，独立滚动/目录，不进入DocumentSession保存来源。原模式/编辑状态/两侧偏好保留，源被另一个标签替代时不强制重新激活。已有保存、恢复、关闭和外部变化协议不被展示模式重写。选择连续阅读，不实现分页、动画或PPT导出。

主进程用窗口WeakMap深度包裹现有原生对话框，确保后台提示和重叠/失败清理也参与进入准入。沿用既定presentation-state字段表达未进入，不加通用错误/窗口IPC。原生菜单按main可知状态置灰，renderer专有历史/备份/待核对还原状态在点击后同一准入拒绝；暂不为视觉菜单同步扩大协议。原生正常进入/退出、锁屏环境下失败恢复、受控事件下UI流程须分别记录，不能互相替代验收。

## ADR-020：保存后历史、固定窗口与独立失败语义

关联REQ-008至016/022/026至028，NFR-001/002/006/007/008。保留ADR-014/017的覆盖前保护，增加正式核验后的新字节历史。固定60秒自动组合并最新节点，手动固定，每文件100条；接受窗口内中间状态不全部可恢复，避免秒级节点迅速挤掉早期内容。合并减少列表密度，不减少每次保存后的I/O。

选择新UUID正文+原子schema2索引+持久retired清理；历史ID不可变，租约覆盖保存/还原/导出。多文件原子提交不作承诺，正文成功与历史失败通过回执和UI分别表达；主/renderer暂停auto，明确手动补记，关闭默认取消确认。generation事件携带路径，阻止同ref另存迁移后旧列表覆盖新列表。代价是额外磁盘写入及复杂的部分成功语义。

## ADR-021：系统打开先排队，再交付就绪界面

REQ-020/021/026，NFR-001/002/008。系统打开事件可能早于界面初始化完成。采用启动同步注册macOS事件、单实例锁及主进程队列，窗口创建共享Promise；新增固定零参数rendererReady业务握手，在主题加载和Vue订阅之后排空请求。仅依赖did-finish-load不足以证明异步初始化后的订阅已安装。重复打开单独要求激活已存在会话，不能把旧正文作为重新载入源。系统打开只复用受控读取/关闭准入/目录监听；Mac关联rank使用Alternate，默认程序仍由用户决定。代价是启动多一步握手及75ms事件合批，依赖原生事件的交付时序。

## ADR-022：复用编辑事务的替换与独立搜索浮层

关联 REQ-005/008/011/013/023/024/026/027/029，NFR-001/002/005/006/007/008。查找快捷键开关面板，打开不自动跳转，用户查询或导航时再定位；面板采用查找/替换页签，仅可编辑源码提供替换。

替换复用现有 CodeMirror ChangeSet、容量/只读/冻结/IME 校验与保存调度，全部替换是单次可撤销事务，不新增可写文本来源或 IPC。浮层不改变工具栏排版，空间不足时向下偏移；接受浮层占用部分正文的成本，避免开关搜索造成相邻控件跳动。

## ADR-023：非模态侧栏与文档独立状态

采用正文滚动宿主与内部居中内容分离；目录最大280px、历史最大300px，均不超过视口30%。宽屏利用留白保持正文位置；窄屏重新分配宽度，正文仍可滚动、选择和编辑。≥960px 两侧可并排，更窄时只展开一侧。开关状态按文档会话保存。

模态抽屉会阻断正文操作，因此使用并排侧栏。目录跳转与历史查看保持侧栏打开；隐藏历史列表和退出预览是独立动作。关联 REQ-008/016/024/026/027、NFR-007/008。

## ADR-024：独立主题偏好

采用主进程管理的 version1 配置和固定读写接口，不引入任意配置 API。浅/深主题是全局偏好，不随文档切换；颜色在根节点统一插值，避免继承文字重复过渡。历史还原保留列表入口，预览工具栏仅提供返回、导出和列表开关。关联 REQ-016/017/024/027/028。

## ADR-025：主动单目标链接与受限图片

选择独立 LinkRouter 和单一业务 IPC，沿用会话去重与资源能力。主动点击直接解析单个本地目标，包括父目录、绝对路径和 file:，不弹额外选择器、不授权整个父目录；被动图片仍受文档目录限制。普通附件只定位，目录打开自身；文字链接用修饰键，图片普通点击。关联 REQ-006/007/021、NFR-001/002/004/008。

使用 sharp 读取元数据而非自写图片解码器，接受分平台原生依赖的维护成本；APNG、SVG 和远程内嵌图保持受限。查看器放大后使用原生滚动，不加入拖动平移。独立行空 a 标记只提取受限 id/name，不开放原始 HTML。链接失败用短暂浮层反馈，避免改变正文布局。

## ADR-026：按展示来源搜索与有限渲染

关联REQ-005/008/021/023/024/026/029、NFR-001/002/005/006/007。统一搜索浮层，阅读采用不修改DOM的Custom Highlight，编辑采用原CodeMirror事务和可见Decoration，避免新增可写文本来源。查询采用字面、非重叠匹配；不支持正则；替换事务与布局见 ADR-022。大文件结果不截断，只限制同时构造的可见Range。图片的地址语法错误与自动加载范围限制分开反馈；外部本地图片继续通过用户点击后的既有单文件授权打开。

## ADR-029：共享、离线且受限的 Markdown 扩展

关联 REQ-002/004/005/016/021/023/029/030、NFR-001/002/005/006/007/008。采用固定版本 markdown-it 插件、highlight.js common、Mermaid strict 和 KaTeX MathML，共享普通阅读/历史/恢复草稿预览/演示管线；原始 Markdown 仍是唯一保存来源。此决策将原基线排除的 Mermaid/公式纳入文档化支持范围，补齐原 REQ-002/004 的任务列表、高亮和复制。

先解析和净化基础正文，再按需加载并绘制富内容；取消旧代数结果，不持久缓存正文。Mermaid 输出二次净化，限制 SVG、图内选择器和 CSS 声明；受限样式使用现有 nonce。KaTeX 禁止信任命令并限制宏展开，采用浏览器原生 MathML，避免增加字体网络能力。少量静态格式/折叠 HTML 通过精确解析规则接纳，其他 HTML 仍显示源码。

流程图和思维导图配色由应用以 base 主题变量指定，其他图型保留分类配色。流程图在净化后增加应用拥有的圆角和标签装饰；思维导图通过测量净化后的图形边界校正文字居中。不改写用户图表语法，不依赖文档提供 CSS，不放开 HTML 标签或资源权限。正文链接使用独立配色，不改变全局按钮与焦点色。

长代码采用视觉换行和高度折叠，减少横向来回滚动及超长块占屏；复制和搜索保留完整源码。代价是视觉行不再一一对应源码行，正式行号与编辑仍以源码为准。高度判断使用代码自身的 ResizeObserver，覆盖窄窗口、缩放和折叠区展开，预览取消时断开观察器。

代价是安装体积和首次绘制耗时增加；复杂图表可能延迟显示，任意样式、HTML 标签、图内配置和私有方言不保证兼容。容量限制和局部源码降级不等同于硬执行超时；两平台性能和原生可访问性需独立验收。范围与上限以 [Markdown 兼容性](markdown.md) 为准。


## ADR-030：独立未命名会话与复用首次保存事务

关联 REQ-008/009/010/011/013/014/015/016/019/021/024/026/027、NFR-001/002/003/005/006/007/008。采用先编辑、首次保存再选路径；新建不生成临时 Markdown，不引入依赖或恢复 schema。无路径会话与 recovered 来源分开表达，显示名仅窗口内递增。原有 CodeMirror、保存屏障、原子写入、历史及恢复机制继续负责内容。

首次保存沿另存为迁移原会话，保留撤销；失联保留请求与冻结快照，通过原 ID 核对结果。相对资源在成功建立路径后才获得基准。空白与 dirty 不能代替恢复维护状态：已备份后清空仍发布空快照，避免崩溃复活旧正文。

单标签关闭提供保存/确认丢弃/取消，保存成功后继续关闭。整窗继续使用全部成功才释放；非空未命名稿停止退出并定位，由用户先处理该文档。接受再次退出的操作成本，避免引入多保存对话框和批量丢弃的整窗事务。


## ADR-031：首页导航与保存操作分区

关联 REQ-009/011/024/026/027、NFR-001/007/008。标签栏 + 改为首页导航，替代此前直接创建未命名文档的入口；欢迎页、菜单和快捷键承担明确的新建动作。首页是无活动文档的视图，不是空白文档标签；接受没有首页专属标签的成本，避免消耗文档名额或生成无意草稿。

保存采用当前文档工具栏中的图标加文字按钮及另存/关闭下拉，仅在编辑状态显示；阅读及预览隐藏整组操作，文件菜单、快捷键和标签关闭保留。保存与文件名、编辑/预览和历史处于同一操作区域；替代窗口标签栏中的保存图标，明确保存只作用于当前文档。接受工具栏重复展示文件名的空间成本，空间不足时分两行。底部展示该文档的状态，避免在目录旁堆放提示。复用现有首次保存、自动保存和恢复事务，不改变源码所有权、保存成功条件或丢回执保护。窄屏状态省略但保留完整可访问名称和悬停提示，失败处理入口继续就地显示在通知区。首页按新建、打开排列，返回首页聚焦首项，视觉顺序与键盘顺序一致。
